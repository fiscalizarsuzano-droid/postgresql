Constraints — Regras de Tabela

Como criar e usar restrições ao modelar seu banco de dados

O que é uma constraint? É uma regra aplicada a uma coluna ou tabela que o banco de dados garante automaticamente. Se um INSERT ou UPDATE violar a regra, o banco rejeita a operação e devolve um erro — sem precisar de validação no código da aplicação.

Exemplo completo — CREATE TABLE com todas as constraints
-- Tabela de referência: categorias CREATE TABLE categorias ( id SERIAL PRIMARY KEY, nome VARCHAR(80) NOT NULL UNIQUE ); -- Tabela principal: produtos com várias constraints CREATE TABLE produtos ( -- Coluna com PRIMARY KEY gerada automaticamente id SERIAL, -- NOT NULL garante que o campo sempre tenha valor nome VARCHAR(120) NOT NULL, -- CHECK valida a regra de negócio: preço maior que zero preco DECIMAL(10,2) NOT NULL CHECK (preco > 0), -- DEFAULT preenche o estoque com 0 se não informado estoque INT NOT NULL DEFAULT 0, -- FOREIGN KEY liga ao id da tabela categorias categoria_id INT NOT NULL, ativo BOOLEAN DEFAULT TRUE, criado_em TIMESTAMPTZ DEFAULT NOW(), -- PRIMARY KEY nomeada como constraint de tabela CONSTRAINT pk_produtos PRIMARY KEY (id), -- FOREIGN KEY com ação ON DELETE e nomeada CONSTRAINT fk_produtos_categoria FOREIGN KEY (categoria_id) REFERENCES categorias(id) ON DELETE RESTRICT ON UPDATE CASCADE, -- UNIQUE garante que dois produtos não tenham o mesmo nome CONSTRAINT uq_produto_nome UNIQUE (nome), -- CHECK de tabela pode verificar múltiplas colunas CONSTRAINT ck_estoque_ativo CHECK (ativo = FALSE OR estoque >= 0) ); -- INDEX para acelerar buscas por categoria (não é constraint, mas anda junto) CREATE INDEX idx_produtos_categoria ON produtos (categoria_id);
PRIMARY KEY Identificador único da linha
PRIMARY KEY simples
coluna
Identifica cada linha de forma única. Automaticamente cria um índice. Não aceita NULL. Cada tabela pode ter apenas uma PK.
id SERIAL PRIMARY KEY -- ou com tipo inteiro explícito id INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY
SERIAL = alias antigo para INT + SEQUENCE. Use GENERATED ALWAYS AS IDENTITY (padrão SQL moderno) para novos projetos.
PRIMARY KEY composta
tabela
Quando a unicidade é definida pela combinação de duas ou mais colunas — tabelas de relacionamento N:N são o caso mais comum.
CREATE TABLE pedido_produtos ( pedido_id INT NOT NULL, produto_id INT NOT NULL, quantidade INT NOT NULL DEFAULT 1, PRIMARY KEY (pedido_id, produto_id) );
A combinação pedido_id + produto_id deve ser única. Cada campo individualmente pode repetir.
PRIMARY KEY nomeada
CONSTRAINT
Nomear a constraint facilita identificá-la em erros e ao fazer ALTER TABLE. Boas práticas recomendam sempre nomear constraints explicitamente.
CONSTRAINT pk_usuarios PRIMARY KEY (id)
Padrão de nome sugerido: pk_nome_tabela — fica fácil identificar em logs de erro.
FOREIGN KEY Integridade referencial entre tabelas
FOREIGN KEY básica
referência
Garante que o valor da coluna existe na tabela referenciada. Se tentar inserir um ID que não existe na tabela pai, o banco recusa.
usuario_id INT REFERENCES usuarios(id) -- forma expandida com nome CONSTRAINT fk_pedidos_usuario FOREIGN KEY (usuario_id) REFERENCES usuarios(id)
A coluna referenciada na tabela pai deve ser PRIMARY KEY ou UNIQUE.
ON DELETE / ON UPDATE
ação
Define o que acontece com os registros filhos quando o registro pai é deletado ou atualizado. É a decisão mais importante de uma FK.
CONSTRAINT fk_exemplo FOREIGN KEY (col_id) REFERENCES tabela_pai(id) ON DELETE CASCADE -- apaga filhos junto ON UPDATE CASCADE -- atualiza filhos junto
DEFERRABLE
avançado
Adia a verificação da FK para o final da transação, não na linha do INSERT. Útil quando duas tabelas se referenciam mutuamente (dependência circular).
CONSTRAINT fk_circular FOREIGN KEY (col_id) REFERENCES outra_tabela(id) DEFERRABLE INITIALLY DEFERRED -- na transação: BEGIN; SET CONSTRAINTS fk_circular DEFERRED; -- inserts que criariam violação temporária... COMMIT; -- verifica tudo aqui
Opções de ação para ON DELETE e ON UPDATE:
CASCADE
Propaga a ação para os filhos. Se o pai é deletado, todos os filhos são deletados também. Se o pai tem o ID atualizado, todos os filhos são atualizados.
RESTRICT
Impede a deleção/atualização do pai se existirem filhos. Verificado imediatamente — o banco bloqueia na hora. Comportamento padrão se nada for especificado.
SET NULL
Quando o pai é removido, a coluna FK nos filhos é definida como NULL. A coluna precisa aceitar NULL para isso funcionar.
SET DEFAULT
Quando o pai é removido, a coluna FK nos filhos recebe o valor DEFAULT da coluna. O DEFAULT precisa referenciar um pai válido existente.
NO ACTION
Similar ao RESTRICT, mas pode ser adiado com DEFERRABLE. A verificação ocorre no final da transação, não imediatamente.
UNIQUE Sem valores duplicados
UNIQUE simples
coluna
Garante que nenhum outro registro tenha o mesmo valor nesta coluna. Diferente da PK, aceita NULL (e múltiplos NULLs são permitidos).
email VARCHAR(255) UNIQUE cpf CHAR(11) UNIQUE NOT NULL slug VARCHAR(120) UNIQUE
UNIQUE cria automaticamente um índice B-tree na coluna, acelerando buscas por aquele campo.
UNIQUE composta
tabela
A combinação das colunas deve ser única — cada coluna individualmente pode ter repetições. Útil para regras como "um usuário só pode seguir cada outro uma vez".
-- usuário não pode seguir alguém duas vezes CONSTRAINT uq_seguidor UNIQUE (seguidor_id, seguido_id) -- produto único por loja CONSTRAINT uq_produto_loja UNIQUE (produto_id, loja_id)
UNIQUE parcial (com WHERE)
índice
Aplica a unicidade apenas em um subconjunto de linhas. Precisa ser feito via índice único parcial — não existe como constraint pura no PostgreSQL.
-- e-mail único só para usuários ativos CREATE UNIQUE INDEX uq_email_ativo ON usuarios (email) WHERE ativo = TRUE; -- slug único por tipo de conteúdo CREATE UNIQUE INDEX uq_slug_tipo ON conteudos (slug, tipo);
Usuários inativos podem ter e-mails que conflitem entre si, mas não com ativos. Padrão muito útil para soft delete.
NOT NULL Campo obrigatório
NOT NULL
coluna
Obriga que o campo sempre tenha um valor. Qualquer INSERT ou UPDATE que tente colocar NULL nesta coluna é rejeitado pelo banco.
nome VARCHAR(100) NOT NULL email VARCHAR(255) NOT NULL criado_em TIMESTAMPTZ NOT NULL DEFAULT NOW()
NOT NULL e DEFAULT combinados garantem: campo obrigatório, mas com valor automático se o INSERT não informar.
Adicionar / Remover via ALTER
alter table
Permite incluir ou retirar NOT NULL de uma coluna já existente sem recriar a tabela.
-- adicionar NOT NULL em coluna existente ALTER TABLE usuarios ALTER COLUMN telefone SET NOT NULL; -- remover NOT NULL (tornar opcional) ALTER TABLE usuarios ALTER COLUMN telefone DROP NOT NULL;
Atenção: para SET NOT NULL funcionar, a coluna não pode ter valores NULL já existentes na tabela.
Trabalhando com NULL
dica
Colunas sem NOT NULL podem conter NULL. Usar as funções certas evita bugs silenciosos em consultas.
-- COALESCE: retorna o primeiro valor não-NULL SELECT COALESCE(apelido, nome, 'Anônimo') FROM usuarios; -- IS NULL / IS NOT NULL para comparar SELECT * FROM usuarios WHERE telefone IS NULL; -- NULLIF: retorna NULL se os valores são iguais NULLIF(estoque, 0) -- retorna NULL se estoque = 0
CHECK Regra de negócio na tabela
CHECK de coluna
coluna
Valida uma condição booleana antes de aceitar o valor. Se a condição for FALSE, o banco rejeita a operação. NULL passa sem erro (IS TRUE seria NULL).
preco DECIMAL(10,2) CHECK (preco > 0) desconto DECIMAL(5,2) CHECK (desconto BETWEEN 0 AND 100) quantidade INT CHECK (quantidade >= 0) status TEXT CHECK (status IN ('ativo','inativo','pendente'))
CHECK de tabela
tabela
CHECK declarado no nível da tabela pode comparar múltiplas colunas entre si — coisa que o CHECK de coluna não consegue fazer.
CONSTRAINT ck_datas_validas CHECK (data_fim > data_inicio), CONSTRAINT ck_preco_desconto CHECK (preco_final <= preco_original), CONSTRAINT ck_entrega_pago CHECK ( status_entrega = 'pendente' OR status_pagamento = 'pago' )
CHECK com expressões
expressão
Qualquer expressão SQL que retorne boolean é válida no CHECK — funções, operadores de string, regex, comparações com LENGTH.
-- comprimento mínimo de senha CHECK (LENGTH(senha_hash) >= 60) -- e-mail com formato básico (regex) CHECK (email ~ '^[^@]+@[^@]+\.[^@]+$') -- CPF com 11 dígitos numéricos CHECK (cpf ~ '^[0-9]{11}$') -- latitude válida CHECK (lat BETWEEN -90 AND 90)
Atenção: CHECKs com funções não determinísticas (como NOW()) podem ter comportamento inesperado.
DEFAULT Valor automático quando não informado
DEFAULT estático
coluna
Define um valor fixo usado quando o INSERT não informa aquela coluna. Pode ser qualquer literal do tipo da coluna.
ativo BOOLEAN DEFAULT TRUE estoque INT DEFAULT 0 pais CHAR(2) DEFAULT 'BR' desconto DECIMAL(5,2) DEFAULT 0.00 permissoes TEXT[] DEFAULT '{}'
DEFAULT com função
dinâmico
O DEFAULT pode ser o resultado de qualquer função SQL. Muito útil para timestamps de criação, UUIDs automáticos e sequências.
criado_em TIMESTAMPTZ DEFAULT NOW() atualizado_em TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP id UUID DEFAULT gen_random_uuid() token TEXT DEFAULT MD5(random()::text) data_hoje DATE DEFAULT CURRENT_DATE
GENERATED (coluna calculada)
gerado
Colunas cujo valor é sempre calculado a partir de outras colunas. O banco mantém automaticamente — você não pode inserir valor manualmente.
preco_unit DECIMAL(10,2) NOT NULL, quantidade INT NOT NULL, -- coluna calculada (sempre atualizada) total DECIMAL(10,2) GENERATED ALWAYS AS (preco_unit * quantidade) STORED, -- busca full-text gerada automaticamente busca TSVECTOR GENERATED ALWAYS AS (to_tsvector('portuguese', titulo)) STORED
STORED = valor salvo em disco (PostgreSQL só suporta este modo atualmente).
Alterar DEFAULT via ALTER
alter table
Modifica ou remove o valor padrão de uma coluna existente. Não afeta dados já inseridos.
-- definir um DEFAULT em coluna existente ALTER TABLE produtos ALTER COLUMN ativo SET DEFAULT TRUE; -- remover o DEFAULT ALTER TABLE produtos ALTER COLUMN ativo DROP DEFAULT;
EXCLUSION Constraint avançada — sem sobreposição
EXCLUDE USING GIST
PostgreSQL
Garante que não haverá dois registros que se "sobreponham" segundo um operador definido. O exemplo clássico é reserva de sala: um horário não pode estar ocupado duas vezes.
-- requer a extensão btree_gist CREATE EXTENSION IF NOT EXISTS btree_gist; CREATE TABLE reservas ( sala_id INT NOT NULL, periodo TSTZRANGE NOT NULL, -- mesma sala não pode ter períodos que se sobreponham CONSTRAINT ex_reserva_sala EXCLUDE USING GIST ( sala_id WITH =, periodo WITH && ) );
&& = operador "se sobrepõe" para tipos RANGE. GIST é o tipo de índice que suporta este operador no PostgreSQL.
EXCLUDE com geometria
espacial
Impede que dois registros referenciem áreas geográficas que se sobrepõem. Útil para zoneamentos, territórios de vendedores, áreas de entrega.
-- com extensão PostGIS CREATE TABLE zonas_entrega ( entregador_id INT NOT NULL, area CIRCLE NOT NULL, CONSTRAINT ex_areas_unicas EXCLUDE USING GIST ( area WITH && ) );
EXCLUSION é exclusiva do PostgreSQL — nenhum outro banco relacional popular tem esse recurso nativo.
INDEX Performance de consulta (não é constraint, mas anda junto)
CREATE INDEX (B-tree)
padrão
Acelera buscas, filtros e ordenação em colunas muito consultadas. B-tree é o tipo padrão — funciona para =, <, >, BETWEEN e ORDER BY.
-- índice simples na coluna email CREATE INDEX idx_usuarios_email ON usuarios (email); -- índice composto (ordem importa!) CREATE INDEX idx_pedidos_usuario_data ON pedidos (usuario_id, criado_em DESC); -- ver se um índice está sendo usado EXPLAIN ANALYZE SELECT * FROM usuarios WHERE email = 'a@b.com';
Índice GIN / GIST
avançado
GIN é ideal para JSONB, ARRAY e full-text search. GIST é para tipos geométricos, ranges e EXCLUSION constraints.
-- GIN para JSONB (busca dentro do JSON) CREATE INDEX idx_meta_gin ON produtos USING GIN (metadata); -- GIN para full-text search CREATE INDEX idx_busca_gin ON artigos USING GIN (busca); -- GIST para RANGE (necessário p/ EXCLUDE) CREATE INDEX idx_periodo_gist ON reservas USING GIST (periodo);
Índice parcial
WHERE
Indexa apenas um subconjunto das linhas. Muito menor e mais rápido que indexar a tabela inteira quando a consulta é sempre filtrada.
-- só indexa pedidos não entregues (minoria ativa) CREATE INDEX idx_pedidos_pendentes ON pedidos (usuario_id, criado_em) WHERE status != 'entregue'; -- só usuários ativos CREATE INDEX idx_usuarios_ativos ON usuarios (email) WHERE ativo = TRUE;
CONCURRENTLY
produção
Cria o índice sem travar a tabela para leituras e escritas. Essencial em tabelas de produção com tráfego. Demora mais, mas não bloqueia usuários.
-- cria sem lock (mais lento, não bloqueia) CREATE INDEX CONCURRENTLY idx_logs_criado ON logs (criado_em); -- remover índice sem lock DROP INDEX CONCURRENTLY idx_logs_criado;
Nunca crie índices sem CONCURRENTLY em tabelas ativas — o lock pode derrubar a aplicação.
Gerenciar Constraints — ALTER TABLE Adicionar, remover e listar constraints existentes
Adicionar constraint
ALTER
Acrescenta qualquer tipo de constraint a uma tabela que já existe, sem precisar recriá-la.
-- adicionar NOT NULL ALTER TABLE produtos ALTER COLUMN nome SET NOT NULL; -- adicionar UNIQUE ALTER TABLE usuarios ADD CONSTRAINT uq_cpf UNIQUE (cpf); -- adicionar CHECK ALTER TABLE produtos ADD CONSTRAINT ck_preco CHECK (preco > 0); -- adicionar FOREIGN KEY ALTER TABLE pedidos ADD CONSTRAINT fk_usuario FOREIGN KEY (usuario_id) REFERENCES usuarios(id);
Remover constraint
ALTER
Remove uma constraint existente pelo nome. Por isso nomear as constraints é tão importante — fica muito mais fácil gerenciá-las depois.
-- remover qualquer constraint pelo nome ALTER TABLE produtos DROP CONSTRAINT ck_preco; ALTER TABLE pedidos DROP CONSTRAINT fk_usuario; ALTER TABLE usuarios DROP CONSTRAINT uq_cpf; -- remover NOT NULL ALTER TABLE produtos ALTER COLUMN nome DROP NOT NULL;
Listar constraints existentes
catálogo
Consulta o catálogo do PostgreSQL para ver quais constraints existem em uma tabela — muito útil para descobrir nomes e depurar erros.
-- listar todas as constraints de uma tabela SELECT conname AS nome, contype AS tipo, -- p=PK f=FK u=UQ c=CHECK pg_get_constraintdef(oid) AS definicao FROM pg_constraint WHERE conrelid = 'produtos'::regclass; -- via information_schema (mais portável) SELECT constraint_name, constraint_type FROM information_schema.table_constraints WHERE table_name = 'produtos';
Desabilitar / Reabilitar constraint
manutenção
Durante migrações ou importações massivas de dados, pode ser útil desabilitar temporariamente FKs e triggers para ganhar velocidade.
-- desabilitar todos os triggers e FKs da tabela ALTER TABLE pedidos DISABLE TRIGGER ALL; -- reabilitar ALTER TABLE pedidos ENABLE TRIGGER ALL; -- revalidar FK após importação ALTER TABLE pedidos VALIDATE CONSTRAINT fk_usuario; -- adicionar FK sem validar dados existentes ALTER TABLE pedidos ADD CONSTRAINT fk_usuario FOREIGN KEY (usuario_id) REFERENCES usuarios(id) NOT VALID;
NOT VALID adiciona a FK sem verificar linhas existentes — muito mais rápido em tabelas grandes. Valide depois com VALIDATE CONSTRAINT.
