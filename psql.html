Numéricos Inteiros · Decimais · Ponto flutuante
INT
ANSI MySQL PgSQL
Número inteiro padrão. O tipo mais usado para IDs, contadores e quantidades do dia a dia.
Tamanho: 4 bytes
Faixa: -2.147.483.648 até 2.147.483.647
Unsigned: 0 até 4.294.967.295
Exemplo: id INT NOT NULL AUTO_INCREMENT
BIGINT
ANSI MySQL PgSQL
Inteiro grande. Use quando INT não é suficiente — timestamps Unix em milissegundos, IDs de redes sociais.
Tamanho: 8 bytes
Faixa: ±9.223.372.036.854.775.807
Exemplo: user_id BIGINT UNSIGNED
SMALLINT
ANSI MySQL PgSQL
Inteiro menor. Economiza espaço quando os valores são pequenos — idades, notas, classificações.
Tamanho: 2 bytes
Faixa: -32.768 até 32.767
Exemplo: idade SMALLINT UNSIGNED
TINYINT
MySQL MSSQL
Inteiro mínimo. Muito usado como substituto de BOOLEAN no MySQL (0 = false, 1 = true). Flags e status simples.
Tamanho: 1 byte
Faixa: -128 até 127
Unsigned: 0 até 255
Exemplo: ativo TINYINT(1) DEFAULT 1
MEDIUMINT
MySQL
Inteiro médio. Pouco usado, mas útil quando SMALLINT é pequeno e INT é grande demais — economia de armazenamento em colunas de alta cardinalidade.
Tamanho: 3 bytes
Faixa: -8.388.608 até 8.388.607
Unsigned: 0 até 16.777.215
DECIMAL / NUMERIC
ANSI MySQL PgSQL
Número decimal de precisão exata. Perfeito para dinheiro, preços e qualquer valor onde arredondamento não é tolerado.
Sintaxe: DECIMAL(precisão, escala)
Ex dinheiro: preco DECIMAL(10, 2)
Armazena: até 65 dígitos no total
⚠ Nunca use FLOAT para valores financeiros
FLOAT
ANSI MySQL PgSQL
Número de ponto flutuante de precisão simples. Use para medidas físicas, coordenadas ou valores científicos onde pequenos erros de arredondamento são aceitáveis.
Tamanho: 4 bytes
Precisão: ~7 dígitos significativos
Exemplo: temperatura FLOAT
DOUBLE
MySQL ANSI
Ponto flutuante de precisão dupla. Mais preciso que FLOAT — usado em cálculos científicos, coordenadas GPS e estatísticas.
Tamanho: 8 bytes
Precisão: ~15 dígitos significativos
PgSQL equiv: DOUBLE PRECISION ou FLOAT8
BIT
MySQL PgSQL MSSQL
Armazena valores em bit. Útil para flags de permissão ou campos booleanos no SQL Server.
Sintaxe MySQL: BIT(n) — n = 1 a 64 bits
SQL Server: BIT = 0 ou 1 (equivale a bool)
Exemplo: permissoes BIT(8)
SERIAL
PgSQL
Atalho do PostgreSQL para criar sequência automática + inteiro. Equivale ao AUTO_INCREMENT do MySQL. Muito usado como chave primária.
Tipos: SMALLSERIAL · SERIAL · BIGSERIAL
Equivale a: INT + SEQUENCE + DEFAULT
Exemplo: id SERIAL PRIMARY KEY
Texto / String Caracteres · Texto livre · Listas
CHAR(n)
ANSI MySQL PgSQL
String de tamanho FIXO. Sempre ocupa n caracteres, preenchendo com espaços se necessário. Ideal quando o valor tem sempre o mesmo comprimento.
Máximo: 255 caracteres
Uso típico: CPF CHAR(11), UF CHAR(2), CEP CHAR(8)
⚠ Espaços extras são removidos na leitura (MySQL)
VARCHAR(n)
ANSI MySQL PgSQL
String de tamanho VARIÁVEL. O tipo de texto mais usado — nomes, e-mails, títulos. Ocupa apenas o espaço necessário.
Máximo MySQL: 65.535 bytes
Máximo PgSQL: sem limite prático (= TEXT)
Uso típico: nome VARCHAR(100), email VARCHAR(255)
TEXT
ANSI MySQL PgSQL
Texto longo sem tamanho definido. Use para descrições, artigos, comentários longos, HTML, markdown — qualquer conteúdo extenso.
MySQL máximo: 65.535 bytes
PgSQL: ilimitado (sem overhead de VARCHAR)
Uso típico: descricao TEXT, conteudo TEXT
TINYTEXT
MySQL
Texto muito curto. Raramente necessário — na prática, VARCHAR(255) é preferido pois é mais flexível para índices.
Máximo: 255 bytes
⚠ Prefira: VARCHAR(255) na maioria dos casos
MEDIUMTEXT
MySQL
Texto médio. Ótimo para artigos de blog, posts longos, ou conteúdo gerado pelo usuário que pode ultrapassar o TEXT comum.
Máximo: 16.777.215 bytes (~16 MB)
Uso típico: artigo MEDIUMTEXT, html_content MEDIUMTEXT
LONGTEXT
MySQL
Texto gigante. Use para logs completos de sistema, dumps de código-fonte, ou qualquer conteúdo massivo em texto.
Máximo: 4.294.967.295 bytes (≈ 4 GB)
Uso típico: log_completo LONGTEXT
ENUM
MySQL PgSQL
Lista de valores permitidos. O banco rejeita qualquer valor fora da lista. Ótimo para status, categorias fixas, tipos de usuário.
Sintaxe: ENUM('val1', 'val2', 'val3')
Exemplo: status ENUM('ativo','inativo','pendente')
⚠ Alterar a lista exige ALTER TABLE
SET
MySQL
Como ENUM, mas permite múltiplos valores de uma lista. A coluna guarda zero, um ou vários itens da lista ao mesmo tempo.
Sintaxe: SET('opcao1', 'opcao2', 'opcao3')
Exemplo: dias SET('seg','ter','qua','qui','sex')
Máximo: 64 membros
NCHAR / NVARCHAR
MSSQL
Versões Unicode de CHAR e VARCHAR no SQL Server. Use quando precisa armazenar caracteres de múltiplos idiomas (chinês, árabe, etc.).
Codificação: UTF-16 (2 bytes por caractere)
Exemplo: nome NVARCHAR(100)
NVARCHAR(MAX): até 2 GB de texto
Data e Hora Datas · Horários · Timestamps
DATE
ANSI MySQL PgSQL
Somente data, sem hora. Ideal para datas de nascimento, vencimentos, datas de eventos, aniversários.
Formato: YYYY-MM-DD
Faixa MySQL: 1000-01-01 até 9999-12-31
Exemplo: data_nascimento DATE
TIME
ANSI MySQL PgSQL
Somente horário, sem data. Útil para horários de funcionamento, duração de algo, ou hora de uma tarefa recorrente.
Formato: HH:MM:SS
Faixa MySQL: -838:59:59 até 838:59:59
Exemplo: horario_abertura TIME
DATETIME
MySQL MSSQL
Data e hora juntas, sem fuso horário. Use para registrar quando algo aconteceu — pedidos, postagens, cadastros. Não se ajusta ao timezone do servidor.
Formato: YYYY-MM-DD HH:MM:SS
Faixa: 1000-01-01 00:00:00 até 9999-12-31 23:59:59
Exemplo: criado_em DATETIME DEFAULT NOW()
TIMESTAMP
MySQL PgSQL
Data e hora com fuso horário. Converte para UTC ao salvar e converte de volta ao ler. Ideal para logs, auditoria e sistemas multi-fuso.
Formato MySQL: YYYY-MM-DD HH:MM:SS
Faixa MySQL: 1970-01-01 até 2038-01-19
PgSQL: TIMESTAMPTZ (inclui tz na leitura)
Exemplo: atualizado_em TIMESTAMP ON UPDATE NOW()
YEAR
MySQL
Armazena apenas o ano com 4 dígitos. Útil para ano de fabricação, modelo, safra, ano de publicação.
Tamanho: 1 byte
Faixa: 1901 até 2155
Exemplo: ano_fabricacao YEAR
INTERVAL
PgSQL ANSI
Representa uma duração ou diferença de tempo, não um ponto específico. Ideal para cálculos como "adicionar 30 dias a uma data".
Exemplos: '3 days', '2 hours', '1 year 2 months'
Uso: NOW() + INTERVAL '7 days'
MySQL: usa INTERVAL em expressões, não como tipo
Binário / BLOB Arquivos · Imagens · Bytes
BINARY(n)
MySQL MSSQL
Dados binários de tamanho fixo. Análogo ao CHAR, mas para bytes. Use para hashes de tamanho fixo como MD5 (16 bytes) ou SHA1 (20 bytes).
Máximo: 255 bytes
Exemplo: hash_md5 BINARY(16)
Diferença: comparação case-sensitive por padrão
VARBINARY(n)
MySQL MSSQL
Dados binários de tamanho variável. Use para senhas criptografadas, tokens de sessão, chaves de autenticação com comprimentos variados.
Máximo: 65.535 bytes
Exemplo: token VARBINARY(64)
BLOB
MySQL PgSQL
Binary Large Object. Armazena dados binários brutos — imagens, PDFs, arquivos de áudio. Na prática, muitos preferem guardar o arquivo em disco e só o caminho no banco.
MySQL máximo: 65.535 bytes
Tipos maiores: TINYBLOB · MEDIUMBLOB · LONGBLOB
PgSQL: BYTEA (equivalente nativo)
TINYBLOB
MySQL
BLOB pequeno. Para arquivos minúsculos ou thumbnails de baixíssima resolução — quase sempre BLOB ou MEDIUMBLOB é mais adequado.
Máximo: 255 bytes
MEDIUMBLOB
MySQL
BLOB médio. Comporta imagens comuns, documentos, ícones — a escolha mais prática quando BLOB básico é insuficiente.
Máximo: 16.777.215 bytes (≈ 16 MB)
LONGBLOB
MySQL
BLOB gigante. Para vídeos, backups, exports de banco inteiros. Use com cuidado — guardar arquivos grandes no banco impacta performance.
Máximo: 4.294.967.295 bytes (≈ 4 GB)
BYTEA
PgSQL
Equivalente do BLOB no PostgreSQL. Armazena sequências de bytes de tamanho variável — imagens, arquivos, hashes, dados encriptados.
Máximo: 1 GB
Exemplo: foto BYTEA, senha_hash BYTEA
Lógico / Especial Boolean · NULL · UUID
BOOLEAN / BOOL
ANSI PgSQL MySQL
Valor lógico verdadeiro ou falso. No PostgreSQL é um tipo real. No MySQL é apenas um alias para TINYINT(1).
PgSQL valores: TRUE, FALSE, NULL
MySQL: alias de TINYINT(1) — 1 = true, 0 = false
Exemplo: ativo BOOLEAN DEFAULT TRUE
UUID
PgSQL MySQL
Identificador único universal de 128 bits. Garante unicidade mesmo entre servidores diferentes — ideal para IDs de sistemas distribuídos e APIs públicas.
Formato: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
PgSQL tipo nativo: UUID (16 bytes)
MySQL: VARCHAR(36) ou BINARY(16) + função UUID()
Exemplo: id UUID DEFAULT gen_random_uuid()
NULL
ANSI
Não é um tipo, mas um estado especial que significa "valor ausente ou desconhecido". Qualquer coluna pode conter NULL a não ser que tenha NOT NULL.
Comportamento: NULL ≠ NULL (use IS NULL para comparar)
Restringir: coluna TIPO NOT NULL
Tratar: COALESCE(col, 'padrão')
MONEY / SMALLMONEY
MSSQL PgSQL
Tipo monetário com símbolo de moeda e 4 casas decimais. Prático, mas DECIMAL(p,s) é mais portável e recomendado para sistemas financeiros sérios.
MSSQL MONEY: 8 bytes, ±922 trilhões
MSSQL SMALLMONEY: 4 bytes, ±214 mil
⚠ Evite: DECIMAL(19,4) é mais portável
JSON / Outros JSON · XML · Geoespacial
JSON
MySQL PgSQL MSSQL
Armazena dados JSON com validação automática de sintaxe. Permite consultas e índices sobre campos internos do JSON — ótimo para dados semi-estruturados.
MySQL: JSON (valida na inserção)
PgSQL: JSON (texto) ou JSONB (binário, indexável)
Exemplo: configuracoes JSON
Consulta: dados->>'campo' (PgSQL)
JSONB
PgSQL
JSON em formato binário no PostgreSQL. Mais rápido para consultas que JSON puro porque já está pré-processado. Suporta índices GIN — o tipo recomendado para JSON no PgSQL.
Vantagem: indexável com GIN/GIST
Desvantagem: leve overhead na escrita
Exemplo: metadata JSONB DEFAULT '{}'
Index: CREATE INDEX ON tabela USING GIN (col)
XML
MSSQL PgSQL ANSI
Armazena documentos XML com validação de estrutura. Permite consultas XPath e XQuery. Muito usado em sistemas legados e integrações B2B/ERP.
MSSQL: Suporte nativo com métodos .query(), .value()
PgSQL: Funções xpath() e xmltable()
Exemplo: nota_fiscal XML
GEOMETRY / GEOGRAPHY
MySQL MSSQL PgSQL
Tipos geoespaciais para coordenadas, rotas, polígonos e formas geográficas. Essenciais para apps de mapas, logística e geomarketing.
Subtipos: POINT, LINESTRING, POLYGON, MULTIPOLYGON
PgSQL: extensão PostGIS (mais poderosa)
Exemplo: localizacao POINT
MySQL: ST_Distance(), ST_Contains()
ARRAY
PgSQL
Armazena uma lista de valores do mesmo tipo em uma única coluna. Elimina tabelas de relação para dados simples como tags, telefones, listas de IDs.
Sintaxe: TIPO[]
Exemplos: tags TEXT[], ids INT[]
Consulta: WHERE 'sql' = ANY(tags)
Índice: CREATE INDEX ON t USING GIN(col)
HSTORE
PgSQL
Armazena pares chave→valor dentro de uma coluna, como um dicionário. Alternativa ao JSON para dados de configuração simples e planos (sem aninhamento).
Requer: CREATE EXTENSION hstore
Exemplo: atributos HSTORE
Acesso: atributos->'cor'
Indexável: sim, com GIN/GIST
PostgreSQL — Tipos Extras Tipos exclusivos e avançados do PgSQL
INET / CIDR
PgSQL
Tipos nativos para endereços IP e redes. INET armazena host + rede; CIDR só aceita endereços de rede (bits de host zerados). Permite operadores de rede nativos.
INET exemplo: ip_cliente INET — '192.168.1.5'
CIDR exemplo: rede CIDR — '192.168.1.0/24'
Operadores: << (contém), >> (está contido)
MACADDR / MACADDR8
PgSQL
Endereço MAC de interface de rede. Aceita formatos como XX:XX:XX:XX:XX:XX. MACADDR8 é para MAC de 8 bytes (EUI-64).
Exemplo: mac_device MACADDR
Função: macaddr_set_bit()
RANGE Types
PgSQL
Armazena um intervalo de valores com início e fim. Perfeito para reservas de hotel, janelas de tempo, faixas de preço. Suporta operadores de sobreposição nativos.
Tipos: INT4RANGE, INT8RANGE, NUMRANGE
Datas: DATERANGE, TSRANGE, TSTZRANGE
Exemplo: periodo DATERANGE
Sobreposição: WHERE periodo && '[2024-01-01,2024-12-31]'
TSVECTOR / TSQUERY
PgSQL
Tipos para busca full-text nativa. TSVECTOR armazena o documento indexado (palavras normalizadas); TSQUERY representa a consulta de busca. Muito mais rápido que LIKE.
Exemplo: busca TSVECTOR GENERATED ALWAYS AS (to_tsvector('portuguese', titulo)) STORED
Consulta: WHERE busca @@ to_tsquery('sql & banco')
Tipos Compostos
PgSQL
Cria tipos personalizados com vários campos, como uma struct. Uma coluna pode guardar um objeto complexo com nome, logradouro e CEP, por exemplo.
Criação: CREATE TYPE endereco AS (rua TEXT, cep CHAR(8))
Uso: endereco_entrega endereco
Acesso: (endereco_entrega).rua
ENUM (PgSQL)
PgSQL
No PostgreSQL, ENUM é um tipo criado explicitamente e registrado no catálogo. Mais robusto que o ENUM do MySQL — tem ordem definida e pode ser expandido com ALTER TYPE.
Criação: CREATE TYPE status_pedido AS ENUM ('novo', 'pago', 'enviado')
Adicionar: ALTER TYPE status_pedido ADD VALUE 'cancelado'
Uso: status status_pedido
